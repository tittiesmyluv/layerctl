# ZTE Libero 5G III (A202ZT) — MTK Preloader で停止、layerctl 到達せず

- 日付: 2026-10-25
- 環境: macOS (Intel) / adb / mtkclient (python3.14 venv, /private/tmp/mtk2)

## 端末
| 項目 | 値 |
|---|---|
| 型番 | A202ZT (ZTE Libero 5G III) |
| SoC | MediaTek MT6833 (Dimensity 700) |
| Android | 12 |
| 画面 | 液晶割れ・漏れ、目視不能 |
| 状態 | Android に到達せず。USB には MediaTek Preloader (0e8d:20ff, HID のみ) として現れる |
| 開発者モード | OFF |
| USB デバッグ | OFF |

## 判定
Android が起動しないため adb が刺さらず、layerctl の対象外。
切り分けは MTK Preloader 段で行う必要がある。

## mtkclient の結果
- Preloader ハンドシェイク: 成功 (電源 + 音量上下 の3ボタン同時押しで USB 接続)
  - CPU: MT6833 / ME_ID / SOC_ID を取得
- target config: SBC=True, SLA=False, DAA=True
- DA アップロードで失敗:
  `upload_data failed with error: Unknown: 0x1d18`
  `Error on uploading da data`

## 原因の当たり
`0x1d18` は `Preloader.send_da` → `upload_data` が返す status。
SBC/DAA 有効個体では署名付き DA が必須で、同梱 DA が撥ねられている。
なお自動選択は `MTK_DA_V6.bin` を最優先で拾う (`daconfig.py` の逆ソート)。
`--loader` を渡すと `bypass_security()` が丸ごとスキップされる。

## 試したもの (すべて 0x1d18)
- 素の printgpt / crash / dumppreloader
- --stock
- --ptype carbonara / kamakiri2
- --loader MTK_AllInOne_DA_2625.bin / MTK_AllInOne_DA_7687.bin

4. mtkclient を 90 秒走らせる
